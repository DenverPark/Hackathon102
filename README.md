# 원단 조합 테스트 — Supabase 연동

작업 브랜치: `backend1` (2026-10-28 사용자 지침). 이후 제작·수정도 이 브랜치에서 진행하며 main 반영은 별도 요청 후 진행합니다.

## 실행

```sh
python -m http.server 8102 --bind 127.0.0.1
```

브라우저에서 http://127.0.0.1:8102/ 를 엽니다. ES module을 사용하므로 index.html을 파일로 직접 열지 마세요. 별도 패키지 설치는 필요 없습니다.

## 실제 연결

- 프로젝트: `czxcnvgbrrakyydtdhgh`
- 목록/상세: `lm_fabrics`, 원단 연구 근거: `lm_evidence`, 출처: `lm_sources`
- 현재 화면 분석: `lm_analyze_catalogue` RPC, 기존 분석 및 길이 계산 RPC는 호환성을 위해 유지
- 브라우저용 공개 설정: `config.js`. publishable 키는 공개 사용 가능한 키이며 secret/service_role 키는 절대 넣지 않습니다.
- 기존 DB는 변경하지 않았습니다. `backend/supabase/`는 이미 적용한 SQL의 인계용 사본입니다. 기존 프로젝트에 초기화 SQL을 재실행하지 마세요.

첫 선택 화면은 main과 같은 원단 카드 6종을 표시합니다. DB에 등록된 나일론·울·데님·코튼 폴리·면직물·폴리에스터 6종을 선택·분석할 수 있습니다. 원단만 선택하며 색상·사전세탁·실측 정보는 입력하지 않습니다. 실제 시료의 시험 자료가 없으므로 검증되지 않은 기획용 가정으로 추정 점수를 표시하며 표준 시험과 연구 출처도 제공합니다.

## 팀 연결 계약

담당 범위는 원단 선택·조회·조합 분석입니다. 상세 테스트 가이드, 결과 저장, 조치 추천, AI 챗봇은 해당 담당자의 API를 연결해야 합니다. 이전 임시 가이드·가짜 저장 성공 및 생산 가능 판정은 실제 API 연결로 오인되지 않도록 연결 대기 화면으로 바꿨습니다.

- `window.LayerMatch.getAnalysis()`는 전체 분석 응답의 복사본 또는 null을 반환합니다.
- 분석 완료 시 `window`에 `layermatch:analysis` CustomEvent가 발생하며 `event.detail`에 전체 응답이 담깁니다.
- `recommended_tests[].test_type`: `shrinkage`, `staining`. 가이드 상세 ID가 아닌 분류 코드입니다.
- 원단 선택 수정 시 이전 분석 응답을 무효화합니다.
- API 계약: `backend/API.md`, 연구 검토: `backend/SOURCE_REVIEW.md`.

## 나일론·울 조사자료 반영 (v0.4.0)

`backend/data/nylon-wool.json`에 조사자료의 프로필2개·출처8개·근거13개를 보관합니다. 원본 PDF는 변경하거나 저장소에 업로드하지 않았습니다. 현재 전체 카탈로그는 원단4개·출처15개·근거23개입니다. 검토 내역은 `backend/NYLON_WOOL_REVIEW.md`, 실제 배포 내역은 `backend/DEPLOYMENT.md`에 있습니다.

기존 프로젝트 업데이트: `backend/updates/nylon-wool-data.sql` 다음 `backend/updates/nylon-wool-analysis.sql` 순서입니다. 기존 테이블을 초기화하지 않습니다. 새 빈 프로젝트 재현 순서는 schema.sql → seed.sql → nylon-wool-data.sql → analysis.sql → scoring.sql → catalogue_scoring.sql → verify.sql입니다. data SQL은 같은 신규 ID에 대해 재실행 가능한 upsert이며, 기존 데님·혼방 행은 바꾸지 않습니다. 코드·자료를 변경할 때는 검토 JSON을 수정한 후 `tools/build-research-update.py`로 데이터 SQL을 재생성하세요.

문서에 연결된 나일론 근거 논문은 실제 양모 연구입니다. 양모 시험 조건도 원문과 충돌합니다. 원문 일부 검증 결과와 원문서 주장을 분리 보관하며, 미확인 값을 안전 기준이나 실제 원단 측정값으로 사용하지 않습니다. PDF에 인용된 동영상은 이번 작업에서 분석하지 않았습니다.


## 이전 호환성 결과 점수 (v0.5.0, 현재 화면에서는 미사용)

결과 페이지는 종합 원형 점수·항목별 막대·원단 쌍별 근거·주의사항을 표시합니다. 점수는 Supabase의 `lm_analyze_scored`가 기존 카탈로그와 사용자 입력을 읽어 계산하며 난수나 임시 원단별 점수를 쓰지 않습니다. 실제 물성 호환성을 검증한 모델이 아니라 기준을 공개한 사전 점검 지수입니다.

네 항목은 소재·가공 정보 확인, 실측 수축률 차이, 실측 첨부포 오염 등급, 사전 세탁 준비이며 각25%입니다. 미확인은0점으로 반영하고 평가정보 확인도를 별도로 표시합니다. 내구성·봉제 적합성은 근거 부족으로 평가하지 않습니다. 원단 쌍별 점수의 평균을 종합 점수로 표시하며 가장 낮은 쌍도 기준 설명에서 확인할 수 있습니다. 상세 환산식·제약은 backend/API.md를 참고하세요.

기존 프로젝트 추가 배포: `backend/updates/compatibility-scoring.sql`. 기존 분석·연구 데이터는 유지합니다. 프론트의 `analyzeScored`가 새 RPC를 호출하고 기존 `analyze`는 유지됩니다.

선택 조회의 ‘실측 정보 입력’에서 내 시료의 측정값만 입력할 수 있습니다. 수축률 입력 시 시험 조건·측정 방향·수축 종류를 함께 입력합니다. 이 입력은 계산용이며 DB에 저장하지 않습니다.

검증: `npm test`(14개), `npm run test:scoring`(실제 점수 API10개). 기존 데이터 회귀 검증은 `npm run test:live`입니다. 브라우저에서 정보 부족 표시, 조건 누락 차단, 검증용3%포인트 차이/오염3등급/세탁완료 입력의72.5점, 모바일 가로 넘침 없음 등을 확인했습니다. 검증용 값은 실제 사용자 시료의 측정값으로 저장하지 않았으며 확인 후 초기화했습니다.

## 이전 원단 프로필 기반 점수 (v0.6.0, 현재 화면에서는 미사용)

선택한 원단 ID만 lm_analyze_catalogue에 전달합니다. 소재 범주에 임의로 부여한 세탁 반응 등급 비교 40%, DB상 비신축 여부 30%, 소재별 관리 확인 가정 30%를 반영합니다. 신축 정보가 불확실하면 해당 점수를 보류하고 나머지 가중치를 재조정합니다. 이염은 평가 보류이며 내구성과 봉제 적합성도 평가하지 않습니다. 각 수치와 가중치는 검증된 표준이나 실험 결과가 아닌 기획 가정입니다. 여러 원단의 결과는 모든 원단 쌍 점수의 평균입니다. 실제 시료 시험을 대신하지 않습니다.

기존 프로젝트 적용: backend/updates/catalogue-scoring.sql. 검증: npm test 및 npm run test:catalogue.

## 시험 근거 기반 평가 (v0.7.0, 현재 화면에서는 미사용)

`lm_analyze_evidence`는 원단 ID만 받아 조합별 세탁 치수 변화, 이염, 봉합강도를 평가 보류로 표시합니다. 확인한 ISO 공식 소개 5건과 국내 논문 초록 2건의 출처와 한계를 DB에 기록합니다. 표준은 시험 방법이지 종합 100점 환산 공식이 아닙니다. 현재 DB에는 실제 선택 원단을 비교한 시험 결과와 제품별 합격 기준이 없어 점수를 산출하지 않습니다. 후속 실측 자료를 등록해도 자동으로 점수가 생기지 않으며, 평가 모델과 검증을 별도 구현해야 합니다. 기존 API는 호환성을 위해 유지합니다.

기존 프로젝트 적용: `backend/updates/evidence-assessment.sql`. 테스트: `npm test`, `npm run test:evidence`.

## 현재 기획용 추정 점수 (v0.7.1)

사용자 요청에 따라 `lm_analyze_catalogue`의 기존 소재 분류 기반 추정 점수를 다시 표시합니다. 수치와 가중치는 임의의 기획 가정이며 실제 시험, 표준 점수나 안전 판정이 아닙니다. 이염은 평가 보류입니다. 표준과 국내 연구는 별도 참고자료로 제공하며 추정 점수를 검증하지 않습니다.

## 면직물·폴리에스터 조사자료 반영 (v0.8.0)

두 조사 PDF의 원단 프로필과 6개 참고 근거, 6개 출처를 추가했습니다. 실제 선택 원단의 혼용률·조직·신축성은 미확인으로 보관하며 연구·조사 수치를 실측값으로 쓰지 않습니다. 시험 기준과 원문 확인 여부는 출처와 함께 표시합니다. 두 원단은 기획용 수축 반응 등급을 각각 면 2, 폴리에스터 1로 임의 확장했으며, 신축 불확실성 때문에 해당 비중을 제외합니다. 이는 검증된 물성 수치가 아닙니다. 기존 프로젝트 적용: `backend/updates/cotton-polyester-data.sql`.

## 6종 동시 선택

선택 조회와 `lm_analyze_catalogue`는 원단 2~6종을 받습니다. 6종을 선택하면 모든 15개 쌍을 분석합니다. 기존 DB에는 `backend/updates/six-fabric-limit.sql`을 적용합니다. 빈 프로젝트를 재현할 때도 원단 데이터 업데이트 이후 이 파일을 적용해야 최신 선택 제한이 유지됩니다. 기존 `lm_analyze`의 시료 입력 계약은 변경하지 않습니다.

## 이염 참고 점수 (v0.9.0)

사용자 요청에 따라 이염 항목에 데님 포함 60점, 그 외 70점의 임의 기획 가정을 표시합니다. 점수는 조사자료의 이염 수치나 시험 결과를 환산한 것이 아니며 실제 원단 조합의 이염 위험, 확률, 견뢰도 등급을 나타내지 않습니다. 색상·염색·가공 정보가 없으므로 종합 점수에 포함하지 않습니다. 다중 원단은 쌍별 가정 점수의 평균입니다. `backend/updates/staining-assumptions.sql`을 기존 프로젝트에 적용합니다.
